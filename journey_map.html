สายการตัดสินใจ — ไม่ใช่เส้นตรงตายตัว ขึ้นอยู่กับ "ความสัมพันธ์เดิม" มากกว่าตำแหน่งในโครงสร้าง

กรณีมีความสัมพันธ์เดิมอยู่แล้ว (บางบัวทอง): แม้ทีมจะเริ่มทำงานกับเจ้าหน้าที่ระดับปฏิบัติการก่อน แต่ ผอ.กอง / ปลัด / นายก เคยทำงานร่วมกับอาศรมศิลป์มาก่อนแล้ว — จึงไม่จำเป็นต้องไต่บันไดทีละขั้นแบบเป็นทางการ ความไว้ใจที่มีอยู่แล้วช่วยย่นระยะเวลาได้มาก แม้จุดเริ่มต้นจะดูเหมือน "ล่างขึ้นบน"

กรณีเริ่มความสัมพันธ์ใหม่ (ไม่มีประวัติร่วมงานมาก่อน): รูปแบบที่ใช้จริงคือ ทีมงาน (ภายนอก) เป็นผู้ขอโอกาสไต่ระดับด้วยตัวเอง ไม่ใช่ปล่อยให้เจ้าหน้าที่ไปโน้มน้าวหัวหน้าภายในตามลำพัง:

  1. เริ่มทำงานระดับชุมชน เจอเจ้าหน้าที่ที่สนใจ
  2. ทีมงานขอโอกาสเข้าไปคุยกับ ผอ.กอง โดยตรง
  3. ถ้า ผอ.กอง สนใจ → ทีมงานขอนำเสนอกับนายกฯ ด้วยตัวเอง

นัยสำคัญที่แก้ไขจากเดิม: สิ่งที่กำหนดความเร็วของ Phase 0 จริงๆ ไม่ใช่ตำแหน่งในโครงสร้าง (บนลงล่าง/ล่างขึ้นบน) แต่แยกเป็น 2 ปัจจัยคนละแบบ — ความเร็วในการ "เริ่มต้น" (Initiation) กำหนดโดยวิสัยทัศน์ของผู้บริหาร (นายกหรือรองนายก) ที่เห็นประโยชน์ + ความไว้ใจสถาบันอาศรมศิลป์ (สั่งสมจากผลงานที่ผ่านมา) ไม่ใช่แค่ "มีความสัมพันธ์เดิม" เฉยๆ ส่วนความเร็วในการ "ดำเนินการ" (Implementation) กำหนดโดยความสนใจของเจ้าหน้าที่ระดับปฏิบัติการ — ในทางปฏิบัติยังไม่เคยเห็น ผอ.กอง ที่ Active จริงจังเลย แม้ตำแหน่งนี้น่าจะเป็นตัวเชื่อมสำคัญตามโครงสร้าง

⚠️ ข้อยกเว้นที่ไร่ขิง (สัญญาณความเสี่ยงใหม่): ความเร็วในการดำเนินการมาจากความเอาจริงเอาจังของตัวรองนายกเอง ที่พยายามผลักดันเจ้าหน้าที่ให้ทำงาน (ซึ่งไม่สำเร็จนัก) — ต่างจากรูปแบบปกติที่ควรมาจากความสนใจของเจ้าหน้าที่เอง

นี่คือkey-person dependency ในอีกรูปแบบหนึ่งที่ยังไม่เคยถูกแมปมาก่อน — ไม่ใช่แค่ Key Connector (อาศรมศิลป์) หรือสถาปนิก/นักกายภาพอาสาที่พึ่งพาคนสำคัญ แต่ความต่อเนื่องของการดำเนินงานในไร่ขิงเองก็พึ่งพารองนายกคนเดียวอยู่ หากรองนายกเปลี่ยน (พ้นตำแหน่ง/หมดวาระ) และเจ้าหน้าที่ยังไม่ได้ถูกดึงเข้ามาอย่างแท้จริง ความเสี่ยงต่อความต่อเนื่องของโครงการที่ไร่ขิงเองอาจสูงกว่าที่เคยประเมินไว้

งบ "พัฒนาศักยภาพผู้พิการ" ไม่ใช่กรณีเดียวกับการอนุมัติซ่อมบ้านรายหลัง

ตัวอย่างบางบัวทอง (งบ "พัฒนาศักยภาพผู้พิการ" ~100,000 บาท/ปี ซึ่งมีอยู่แล้วทุกปี) ไม่ใช่กรณี "อนุมัติซ่อมบ้านหลังไหน" แต่เป็นเรื่องการจัดสรรงบประจำปีที่มีอยู่แล้วให้ทำกิจกรรมรูปแบบใหม่ (เปลี่ยนจากใช้อย่างอื่นมาเป็นจ้างนักกายภาพ):

  • การเปลี่ยนรายละเอียดว่าจะจัดงบก้อนนี้แบบไหน เป็นสิทธิของเจ้าหน้าที่เอง
  • อาจต้องนำเสนอด้านบนเพื่ออนุมัติ — แต่ถ้าอยู่ในกรอบการดำเนินงานที่ทำได้อยู่แล้ว ไม่น่าจะถูกปฏิเสธ

นี่เป็นเส้นทางที่มีแรงเสียดทานต่ำกว่ามากเมื่อเทียบกับการขอ "งบใหม่" — อาจเป็นทางลัดที่คุ้มค่าที่สุดสำหรับพื้นที่ใหม่: เช็คว่าเทศบาลมีงบหมวดคล้ายกันอยู่แล้วหรือไม่ แล้วเสนอ "ปรับรายละเอียดการใช้" แทนที่จะขอ "งบใหม่"

⚠️ ข้อควรระวัง (ยังไม่ยืนยันว่าใช้ได้ทั่วไป): ยังไม่แน่ใจว่า อปท. อื่นมีงบก้อนนี้เหมือนกันหรือไม่ — แม้ชื่อคล้ายกัน ขอบเขตการใช้จ่ายอาจต่างกันมาก ตัวอย่าง: ทต.หนองเสือ มี "งบพัฒนาศักยภาพผู้สูงอายุ" เช่นกัน แต่ระบุให้ใช้กับการพาผู้สูงอายุไปศึกษาดูงานเท่านั้น — ไม่ใช่งบที่ยืดหยุ่นสำหรับจ้างนักกายภาพหรือปรับบ้านแบบบางบัวทอง

นัยสำคัญ: ชื่องบที่ฟังดูคล้ายกันไม่ได้แปลว่าใช้งานได้แบบเดียวกันทุกที่ — ต้องเช็คขอบเขตการใช้จ่ายที่ระบุไว้จริงของแต่ละ อปท. เป็นรายกรณี ก่อนเสนอแนวทางนี้กับพื้นที่ใหม่ (ไร่ขิง/หลักหก/บางปู)

เรื่อง MOU — ไม่ใช่เงื่อนไข แต่ทำให้ใครอยากได้ก็ได้

  • MOU ไม่จำเป็นและไม่ใช่เงื่อนไขในการเริ่มทำงาน
  • กรณีบางบัวทอง: เจ้าหน้าที่เป็นฝ่ายขอเซ็น MOU เอง — ทีมงานยินดีถ้าฝ่ายไหนต้องการ แต่ไม่บังคับ ถ้าทำงานได้โดยไม่มี MOU ก็ไม่เป็นไร

ความกังวลจริงของเจ้าหน้าที่ระดับปฏิบัติการ (แยกจากผู้บริหาร)

ผู้บริหาร: ส่วนใหญ่เห็นประโยชน์และสนใจอยู่แล้ว

เจ้าหน้าที่ระดับปฏิบัติการ: กังวลว่าเป็นภาระงานเพิ่ม โดยเฉพาะถ้าเคยลองทำมาก่อนแล้วรู้ว่ายาก (ทั้งเรื่องเอกสารและการจัดการงบประมาณ) — ยอมรับว่าปีแรกท้าทายจริงในแง่การรวบรวมข้อมูล/สร้างการมีส่วนร่วม

รูปแบบที่พบบ่อย: ถ้าเจ้าหน้าที่อยากทำ ผู้บริหารมักสนับสนุนตาม — ทิศทางนี้ (staff-driven) ดูจะได้ผลมากกว่าทิศทางตรงข้าม (ผู้บริหารสั่งลงมาแต่เจ้าหน้าที่ไม่อิน)

⚠️ Pain Point ใหม่: การจัดการความคาดหวังของเจ้าของบ้าน

เจ้าหน้าที่กังวลเรื่องหนึ่งที่เป็นรูปธรรมมาก: การลงพื้นที่เยี่ยมบ้านเพื่อประเมิน อาจทำให้เจ้าของบ้านเข้าใจว่า "เทศบาลต้องมาปรับปรุงให้แน่นอน" — ถ้าระหว่างดำเนินการ (หรือสุดท้ายไม่มีงบจริง) เจ้าของบ้านจะคอยติดตามถาม หรือรู้สึกว่าเทศบาลมาดูแล้วไม่ช่วย จนกลายเป็นโกรธเทศบาล

นี่คือการปรากฏตัวจริงของความเสี่ยง "community expectation management" ที่เคยแมปไว้แล้วในการวิเคราะห์ MOU กับคณะสถาปัตยกรรมศาสตร์ — ตอนนี้เห็นชัดว่าเกิดขึ้นได้ตั้งแต่ขั้น Phase 0 / ก่อนเริ่มงานเลย ไม่ใช่แค่ตอนออกแบบ

แนวทางที่เสนอ (มุมมองทีมงาน): เทศบาลมีสิทธิบอกตรงๆ ว่า "พยายามจะช่วย แต่รับประกันไม่ได้" — ถ้าสุดท้ายไม่ได้จริงๆ ก็อธิบายให้เข้าใจ ถ้าเขาไม่เข้าใจจริงๆ ก็ต้องปล่อยไป (ไม่ใช่ทุกเคสจะจบสวยงามได้)

กรณีตัวอย่างจริงของการปฏิเสธ (Phase 0 Rejection Case)

เทศบาลเมืองบางศรีเมือง — ปฏิเสธไม่เข้าร่วม โดยให้เหตุผลว่า "ไม่มีกรณีผู้พิการด้านการเคลื่อนไหวที่ต้องการปรับปรุงบ้าน" ในพื้นที่

⚠️ ข้อสังเกตสำคัญ: เชื่อว่าเหตุผลนี้มาจากการไม่มีข้อมูลเชิงรุกในพื้นที่ (ไม่ใช่เพราะไม่มีคนต้องการจริง) — และเทศบาลนี้ก็ไม่สนใจทำสำรวจเชิงรุกด้วย ทำให้เกิดวงจรปิด: ไม่สำรวจ → ไม่เห็นข้อมูล → สรุปว่าไม่มีความต้องการ → ไม่ต้องทำโครงการ

นี่คือหลักฐานที่ยืนยันสมมติฐานเดิมที่ตั้งไว้ตอนต้น: ปัญหา Phase 0 (ไม่เข้าร่วม) กับ Phase 1 (ไม่มีข้อมูลเชิงรุก) เป็นเรื่องเดียวกันได้จริง ไม่ใช่แค่ทฤษฎี

ประเด็นที่ถามไปก่อนหน้า — ได้คำตอบแล้ว

"ความเป็นธรรมในการคัดเลือกบ้านเป็นความกังวลของเทศบาลก่อนตกลง Phase 0 หรือไม่?" → ไม่น่าจะใช่ ตามการประเมินของทีมงาน เพราะถ้าทำแบบเชิงรับ (ไม่แจ้งมาไม่ได้ซ่อม หรือเรียงคิวมาก่อนได้ก่อน) เทศบาลอธิบายได้ง่าย และผู้นำชุมชน/อสม. ก็ไม่ได้มีส่วนร่วมในการตัดสินใจเลือกอยู่แล้วในทางปฏิบัติจริง — ดังนั้นนี่ไม่ใช่ตัวแปรที่ทำให้เทศบาลลังเลตั้งแต่ต้น (ต่างจากที่ตั้งสมมติฐานไว้ก่อนหน้า)

ไร่ขิง — Timeline ของ Buy-in: ก่อนเข้าสู่ 2 ปีปัจจุบัน มีช่วงเริ่มสนใจมาก่อนแล้วอีกประมาณ 2 ปี (รวมแล้ว buy-in ใช้เวลาหลายปีกว่าจะมาถึงจุดนี้) — จุดเปลี่ยน (turning point) คือเห็นผลงานจริงจากแบบที่สถาปนิกทำ และเห็นว่าช่วยกลุ่มเปราะบางได้จริง ไม่ใช่แค่การอธิบายเชิงหลักการ ("seeing is believing" มากกว่า "telling")

แผนที่ฐานข้อมูล (Data Landscape) — ทำไมข้อมูลถึงกระจัดกระจาย

ฐานข้อมูลที่ 1: กองสวัสดิการ อปท. — มีข้อมูลผู้สูงอายุ + ผู้พิการ "ทุกคนที่ลงทะเบียนแล้ว" เท่านั้น เงื่อนไข: (1) ย้ายทะเบียนบ้านมาอยู่ในพื้นที่แล้ว และ (2) ลงทะเบียนผู้พิการกับ อปท. แล้ว — จุดบอด: คนที่อาศัยอยู่จริงแต่ไม่ได้ย้ายทะเบียนบ้าน หรือยังไม่ได้ลงทะเบียนผู้พิการ ไม่มีข้อมูลในระบบนี้เลย ในเทศบาลขนาดใหญ่ (เช่น เทศบาลนครบางบัวทอง — ตัวอย่างเปรียบเทียบ ไม่ใช่หนึ่งใน 3 พื้นที่โครงการ) งานผู้สูงอายุกับงานกลุ่มเปราะบางอาจแยกคนละคนดูแล แม้จะอยู่กองเดียวกัน

ฐานข้อมูลที่ 2: อสม. / รพ.สต. — มีข้อมูลละเอียดและครอบคลุมมากที่สุด เพราะลงพื้นที่จริงในระดับชุมชน เป็นคนละหน่วยงานกับกองสวัสดิการ อปท. ข้อมูลไม่ได้เชื่อมกันอัตโนมัติ

✅ ยืนยันโครงสร้างจากการสืบค้น: อสม./รพ.สต. อยู่ในสายกระทรวงสาธารณสุขทั้งหมด ไม่ได้สังกัด อปท. — รพ.สต. ใช้ระบบ HOSxP_PCU ส่งข้อมูลมาตรฐาน "43 แฟ้ม" เข้า HDC (Health Data Center) ซึ่งเป็นฐานข้อมูลระดับประเทศของกระทรวงสาธารณสุข; อสม. มีระบบทะเบียน/ติดตามของตัวเองคือ "ระบบสารสนเทศงานสุขภาพภาคประชาชน" ดูแลโดยกรมสนับสนุนบริการสุขภาพ ส่วนกองสาธารณสุขฯ ของ อปท. เป็นฐานข้อมูลแยกต่างหาก ไม่เชื่อมกับ HDC — ทำงานร่วมกับ อสม. ได้ในทางปฏิบัติ แต่ไม่ได้กำกับดูแล อสม. โดยโครงสร้าง และไม่ได้ใช้ฐานข้อมูลเดียวกันกับ รพ.สต.

ความครอบคลุมของข้อมูลชุดนี้ขึ้นอยู่กับความขยัน/ความละเอียดของแกนนำและ อสม. แต่ละคน ไม่ใช่ระบบที่รับประกันความครบถ้วน — ตัวอย่าง ทต.หลักหก: แม้ รพ.สต. จะเข้าร่วมประชุม อสม. อย่างเข้มแข็ง แต่ก็ยังตกสำรวจผู้สูงอายุ/กลุ่มเปราะบางบางส่วนอยู่ดี

ข้อสังเกต: 4 ช่องทางแรกไม่มีช่องทางไหนที่ตั้งต้นจาก "ระบบกลาง" ที่ครอบคลุมทั้งพื้นที่ได้ในตัวเอง — ทุกช่องทางพึ่งพาความร่วมมือแบบ ad-hoc ระหว่างหน่วยงาน ซึ่งอาจเป็นสาเหตุหนึ่งที่ทำให้ Phase 0 (Buy-in) ยากสำหรับเทศบาลบางแห่ง เพราะมองไม่เห็น "ระบบที่ชัดเจน" ตั้งแต่ต้น มีแต่ "กระบวนการที่ต้องประสานเอง"

⚠️ ระบบคัดกรองและจัดลำดับความสำคัญ — ความเสี่ยงเรื่องความเป็นธรรม

หลังจากรวบรวมรายชื่อกลุ่มเป้าหมายมาแล้ว ยังมีปัญหาอีกชั้นหนึ่งคือ "ใครควรได้ก่อน" — แต่ละเส้นทางงบใช้เกณฑ์ต่างกัน และมีความเสี่ยงต่างกัน:

เส้นทางบ้านพอเพียง (สภาองค์กรชุมชน): ใช้กรอบ "ความจำเป็น + ความยากลำบาก" พิจารณาโดยคณะกรรมการ

⚠️ ดุลพินิจของคณะกรรมการในบางกรณีอาจไม่สมเหตุสมผลนัก (สังเกตได้จากบางกรณีในไร่ขิง) — มีความเสี่ยงเรื่องระบบพวกพ้องได้ เพราะไม่มีเกณฑ์เชิงปริมาณที่ตรวจสอบย้อนกลับได้ชัดเจน

เส้นทางเทศบาล (งบ อปท./พมจ. ทั่วไป): บางพื้นที่ใช้ระบบ "มาก่อนได้ก่อน" ควบคู่กับดุลพินิจ บางพื้นที่พิจารณาเฉพาะในกลุ่มผู้ที่มาขอรับความช่วยเหลือเท่านั้น

⚠️ ความเสี่ยงเชิงระบบที่สำคัญ: ทั้งสองแบบเป็นระบบเชิงรับ (passive) — คนที่ยากลำบากจริงแต่ไม่มีตัวแทน (ผู้นำชุมชน/อสม.) มาร้องขอแทน หรือไม่ได้ร้องขอด้วยตัวเอง จะไม่ได้รับการช่วยเหลือเลย แม้จะสมควรได้รับมากที่สุดก็ตาม — นี่ไม่ใช่ปัญหาระดับปัจเจก แต่เป็นช่องโหว่เชิงระบบที่ทำให้กลุ่มเปราะบางที่สุด (ซึ่งมักไม่มีเครือข่ายทางสังคมด้วย) ถูกทิ้งไว้ข้างหลังซ้ำซ้อน

โมเดลในอดีตที่เคยใช้: โครงการเคยใช้วิธีสำรวจ+คัดกรองแบบมีส่วนร่วมของคนในชุมชน เพื่อจัดลำดับความสำคัญและความต้องการ — ทำไปพร้อมกับความต้องการด้านอื่นๆ ของชุมชน ไม่ใช่แค่เรื่องบ้านอย่างเดียว

ทิศทางที่อยากผลักดัน (ระยะยาว): ผลักดันให้ อปท. มีระบบคัดกรองแบบมีส่วนร่วม เช่น ใช้เวทีประชาคมของเทศบาลเมืองไร่ขิง (ซึ่งมีกลไกนี้อยู่แล้ว) เป็นพื้นที่พิจารณาลำดับความจำเป็นเรื่องปรับบ้านด้วย

กลยุทธ์ปีแรก (interim): พิจารณาจากข้อมูลที่มีอยู่ก่อน แต่สื่อสารให้แกนนำชุมชน/อสม. เห็นชัดว่า ถ้าพวกเขาช่วยหาข้อมูลกลุ่มเปราะบางที่จำเป็นจริงมาเสนอ อปท. จะพิจารณาด้วยเกณฑ์นี้และช่วยเหลือได้จริง — สร้างแรงจูงใจเชิงบวกให้แกนนำ/อสม. ลงพื้นที่สำรวจเชิงรุกมากขึ้น

คำถามที่ควรถามในการสัมภาษณ์รอบถัดไป: ไร่ขิง/หลักหก/บางปู แต่ละที่ใช้เกณฑ์ไหนในทางปฏิบัติจริง? เคยมีเคสที่ "ตกหล่น" เพราะไม่มีตัวแทนมาร้องขอหรือไม่? เวทีประชาคมของไร่ขิงจัดถี่แค่ไหน และมีช่องให้หยิบยกประเด็นนี้ได้จริงหรือไม่?

ช่างมืออาชีพฝีมือดีกว่าค่าแรงสูง กินงบจนเหลือค่าวัสดุน้อย — ส่วนใหญ่ที่ใช้ได้จริงคือช่างที่เต็มใจช่วยเหลือโดยคิดราคาไม่แพง (บางครั้งแทบไม่มีกำไรหรือขาดทุนเล็กน้อย) พึ่งพาน้ำใจอีกชั้นหนึ่ง เหมือนสถาปนิก/นักกายภาพอาสา

กลไกที่ช่วยได้จริง: ช่างส่วนใหญ่ไม่เข้าใจ Universal Design แต่แบบก่อสร้างที่ชัดเจนจากสถาปนิกช่วยแก้ปัญหานี้ได้ — เป็นการถ่ายทอดความรู้เป็นทอดๆ: นักกายภาพบำบัด (รู้ความจำเป็นทางร่างกาย) → สถาปนิก (แปลงเป็นแบบ) → ช่าง (ทำตามแบบได้ถูกต้องแม้ไม่เข้าใจหลักการ Universal Design เอง)

⚠️ การกำกับหน้างาน — จุดที่ "ยังไม่ลงตัว"

สถาปนิกอาสาไม่ได้กำกับหน้างานอย่างเป็นทางการ — อาจลงพื้นที่คุยกับช่างระหว่างงานเพื่อให้เข้าใจแบบตรงกัน แล้วประสานงานต่อทางออนไลน์ ปัญหาที่ยังไม่มีทางแก้ชัดเจน: เวลาเจอปัญหาหน้างาน บางครั้งปล่อยให้ช่างตัดสินใจเอง ซึ่งทีมงานเองก็ยอมรับว่า "ไม่ค่อยดีนัก" — สาเหตุคือสถาปนิกอาสาน่าจะไม่มีเวลามากพอจะลงพื้นที่บ่อยขนาดนั้น (ข้อจำกัดโดยธรรมชาติของโมเดลอาสาสมัคร)

นี่คือความเสี่ยงที่เชื่อมกับประเด็น "ความรับผิดชอบทางวิชาชีพ" ที่เคยแมปไว้ใน MOU (Phase 3) — ถ้าช่างตัดสินใจเองหน้างานแล้วเกิดปัญหาเชิงโครงสร้างภายหลัง ใครรับผิดชอบ ยังเป็นคำถามเปิด

✅ ความสัมพันธ์กับเจ้าของบ้านระหว่างก่อสร้าง — ดีกว่าที่กังวลไว้

ต่างจากความกังวลของเจ้าหน้าที่ใน Phase 0 พบว่าเมื่องานเริ่มทำจริงแล้ว ปัญหาน้อยกว่าที่คาด: เจ้าของบ้านไม่ค่อยมีปัญหา ถ้าช่างมีนิสัยดี เรื่องแบบอาจมีปัญหาบ้าง (เช่น ไม่ตรงใจ) แต่เนื่องจากเป็นงบเทศบาล เจ้าของบ้านมักเข้าใจข้อจำกัดได้เอง — ไม่ต้องอธิบายมากเหมือนที่กังวลไว้

นัยสำคัญ: ความเสี่ยงเรื่อง "การจัดการความคาดหวัง" ที่แมปไว้ใน Phase 0 น่าจะรุนแรงที่สุดก่อนเริ่มงาน (ตอนไปสำรวจแล้วไม่ได้งบ) มากกว่าระหว่างทำงานจริง — ควรโฟกัสการจัดการความคาดหวังไปที่ช่วงก่อนอนุมัติงบมากกว่าช่วงก่อสร้าง

งบและเวลา — ยังไม่เจอปัญหา แต่มีเงื่อนไขแฝง

เท่าที่ทำมายังไม่เจอปัญหางบ/เวลาเกินแผน เพราะแบบที่ชัดเจนทำให้ช่างทำงานง่ายและเร็ว — แต่มีเงื่อนไขแฝงที่สำคัญ: นี่ใช้ได้ก็ต่อเมื่อช่างอ่านแบบเทคนิคเป็น ถ้าช่างอ่านแบบไม่ได้ก็อาจเกิดปัญหาได้เช่นกัน — "ช่างที่อ่านแบบก่อสร้างเป็น" จึงเป็นทักษะที่จำเป็นแฝงอยู่ที่ยังไม่เคยถูกระบุเป็นเกณฑ์คัดเลือกช่างมาก่อน

การตรวจรับ — ไม่เป็นทางการ เน้นป้องกันล่วงหน้ามากกว่าตรวจสอบย้อนหลัง

เทศบาลร่วมกับทีมงานตรวจรับ — ส่วนใหญ่มีลักษณะอะลุ่มอะหล่วยกัน ไม่ใช่การตรวจสอบมาตรฐานที่เข้มงวด กลยุทธ์หลักที่ใช้จริงคือป้องกันตั้งแต่ต้นทาง: พยายามหาช่างที่ดีและมีประสบการณ์ก่อนเริ่มงาน มากกว่าพึ่งการตรวจสอบคุณภาพหลังส่งมอบ

คำถามที่ควรติดตามต่อ: ถ้าไม่มีมาตรฐานตรวจรับที่เป็นทางการ จะรู้ได้อย่างไรว่างานที่ทำเสร็จตรงตาม Universal Design จริง? นี่อาจเป็นช่องว่างที่ควรมี checklist ง่ายๆ ให้เทศบาล/ทีมงานใช้ตรวจรับ

  1. Phase 0 (Buy-in): ✅ ยืนยันแล้วว่า Phase 0 ↔ Phase 1 เชื่อมกันจริง (กรณีบางศรีเมือง: ไม่สำรวจเชิงรุก → ไม่เห็นข้อมูล → สรุปว่าไม่มีความต้องการ → ปฏิเสธเข้าร่วม) — ไม่ใช่แค่สมมติฐานอีกต่อไป
  2. Phase 4 (Supply/งบ): จุดเปราะที่สุด — แต่ยืนยันแล้วว่างบรัฐมีสนับสนุนอยู่ ความลังเลของเทศบาลน่าจะมาจาก "ไม่เคยทำ+จินตนาการว่ายาก" หรือ "เคยทำแล้วรู้ว่ายาก" มากกว่าไม่รู้จะหางบจากไหน
  3. Phase 6 (Sustainability): ยังไม่มีต้นแบบที่ชัดเจนแม้แต่ในไร่ขิง — และตอนนี้เห็นความเสี่ยง Key Connector transfer เกิดขึ้นจริงแล้วที่หลักหก (คุณแตนลาออก)
  4. ใหม่ — การจัดการความคาดหวังของเจ้าของบ้าน: เป็น pain point ที่ตัดขวางหลาย Phase (เริ่มกังวลตั้งแต่ Phase 0 แต่ผลกระทบจริงอยู่ที่ Phase 2/5) — ควรมีแนวทางสื่อสารมาตรฐานให้เจ้าหน้าที่ใช้พูดกับเจ้าของบ้าน ("พยายามช่วย แต่รับประกันไม่ได้")
  5. ปิดประเด็นแล้ว: ความเป็นธรรมในการคัดเลือกบ้านไม่ใช่ปัจจัยที่ทำให้เทศบาลลังเลใน Phase 0 — เป็นคนละเรื่องกับ pain point ระบบคัดกรองที่คุยไว้ใน Phase 1 (ซึ่งยังคงเป็นปัญหาอยู่ แต่ไม่ใช่สาเหตุของการปฏิเสธเข้าร่วมโครงการ)

ขั้นต่อไป (แนะนำ)

  • คุยรายละเอียดกับคุณโป้ง (พยาบาลคนใหม่ที่หลักหก) เพื่อประเมินว่าจะรับช่วง Key Connector role ได้จริงหรือไม่
  • นำ Journey Map นี้ไปเทียบกับพื้นที่บางปู (ใหม่สุด, เทศบาลยังลังเล) → เช็คว่าเข้าข่าย "ไม่เคยทำ" หรือ "เคยทำแล้วรู้ว่ายาก" แบบไหน
  • สัมภาษณ์ สท.อ๊อด (ไร่ขิง) เจาะรายละเอียดช่วง 2 ปีก่อนหน้าที่เริ่มสนใจ — อยากรู้ว่า "เห็นผลงานจากสถาปนิก" ครั้งแรกเกิดขึ้นอย่างไร เพื่อจำลองจุดเปลี่ยนนี้ให้บางปู/หลักหกได้
  • ร่างแนวทางสื่อสารมาตรฐาน "พยายามช่วย แต่รับประกันไม่ได้" ให้เจ้าหน้าที่ใช้พูดกับเจ้าของบ้านระหว่างลงพื้นที่ประเมิน
  • เจาะ Phase 4 โดยเฉพาะเรื่องแหล่งงบประมาณที่เทศบาลแต่ละแห่งเข้าถึงได้จริง
